## 3. Architecture improvements

1. One authorized snapshot (`bootstrap`) replaces a per-view RPC fan-out; `taskIndex` adds compact
   columnar task summaries.
2. A client store paints synchronously, deduplicates in-flight reads, discards superseded
   responses and keeps unrelated cached views after a write.
3. Stale-while-revalidate with per-dataset freshness, explicit indicators and revocation handling
   replaces the 30-second expiry plus whole-cache clear.
4. Local filtering mirrors the server filters while the explicit search stays authoritative.
5. `Tasks.list` no longer loads projects/subprojects for unfiltered reads.

- The TASKS table is still scanned server-side; Sheets has no index.

## 9. Exact DEV deployment steps

Nothing was deployed automatically. An authorized operator performs, in this order, in the **DEV**
project only:

1. `git fetch` and confirm the delivery commit; check `git status` is clean apart from intended
   files.
2. `npm ci`, `npm run lint`, `npm test`, `npm run validate`,
   `node scripts/manager-web-benchmark.js`.
3. Confirm `src/appsscript.json` still has `webapp.access = DOMAIN` and
   `executeAs = USER_ACCESSING`, and that no new scope was added.
4. `npx clasp login` and confirm the DEV `.clasp.json`: script project, not the dashboard project,
   not production.
5. `npx clasp status` then `npx clasp push` into DEV. Create a new deployment version rather than
   editing the existing one in place.
6. Keep `MANAGER_WEB_ALLOWED_DOMAINS` set for DEV before opening the URL.
7. Open the DEV web app as an ADMIN, then as a MANAGER, then as an employee (must be refused).
8. Run the 20-case smoke plan in [MANAGER_WEB_APP_SMOKE_TEST.md](../MANAGER_WEB_APP_SMOKE_TEST.md)
   and record the measured values (account, dataset, timestamp, execution ID, deployment version).
