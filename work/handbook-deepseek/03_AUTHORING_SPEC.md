# 制作仕様・根拠・配布前チェック

このファイルは執筆者向けです。利用者向け本文に開発者向け情報を混ぜないでください。

## 1. 研修の設計

最短導線を先頭に置き、詳細は必要になったときに読める構成とします。画面一覧から説明を始めないでください。

### メンバーの到達課題

「自分の担当を発見 → 内容と納期を理解 → 実施 → 完了報告 → 判断の確認」。新規登録は次の段階で教えます。

### マネージャーの到達課題

「期限と判断待ちを把握 → 対象を確認 → 担当・日程を整える → 申請を判断 → 結果を確認」。初期設定はサーバー設定ではなく、業務の分野・案件・タスク・担当を整えることを指します。

### レッスンの型

各レッスンを次の順に組み立てます。

1. **目的**：何ができるようになるか。
2. **対象・開始画面**：MEMBER/MANAGER とメニュー名。
3. **事前条件**：作成先、入力情報、作業状態など。
4. **実画面**：全体像1枚、必要なら操作部分の拡大1枚。
5. **クリック手順**：番号①〜⑤と対応させる。
6. **成功の確認**：保存・受付・承認などの違いを具体的に示す。
7. **次の行動**：確認画面・申請履歴などへ誘導。
8. **よくあるつまずき**：その手順に関係する注意を1つだけ添える。

「5分」「10分」などの時間は研修の目標としてのみ扱い、実測の完了時間と書かないでください。

### 追加撮影が必要な場面

- ログイン、初回パスワード変更、アカウントメニュー。
- メンバーのサブプロジェクト作成、作成後の成功画面。
- マネージャーの分野作成、メンバー参照、タスク新規作成、担当者追加。
- マネージャーのプロジェクトフォーム下部（公開設定・確定操作）。
- 保存成功、受付完了、承認後の完了、承認後の期限変更。
- 却下・差戻しの結果、競合、受付停止、送信結果不明の各状態。
- マネージャーの担当・期限レポートとメンバーのタイムライン。

本番で練習レコードや申請を作って撮影しないでください。状態遷移は隔離した検証環境のサンプルを使用します。画面を偽造して検証済みとすることは禁止です。

## 5. 既知の表記・証拠の制限

1. **完了メモの必須性**：画面ラベルは「任意」。実装は空文字を拒否する。本文は必ず書く手順にし、不一致をレビュー事項として残す。
2. **申請一覧の列見出し**：内容欄に、申請IDを控えるよう促す長い文が表示される。図から推測で正しい短い見出しへ描き換えない。
3. **フィクスチャ**：集計値と表示件数、日程、作業のプロジェクト対応等は操作説明用であり、分析教材として整合性を保証していない。数値を使ってKPI計算を教えない。
4. **現行ソースと本番**：旧トップナビゲーションの保存画像は不採用。今回の左ナビゲーションが本番にも配信済みとは主張しない。
5. **遷移結果**：作成、保存、申請送信、判断確定は実行していない。操作後の説明はソースに基づく。画面キャプチャによる実証と混同しない。
6. **画面にないボタン**：役割、対象状態、受付設定によって表示が変わる。常に存在すると断言しない。

## 6. 配布前受入チェック

- [ ] 配布対象のアプリ版とナビゲーション・ラベルが一致している。
- [ ] MANAGER/MEMBERを実際に切り替えた検証環境で、主要手順を確認した。
- [ ] 本人アカウントでログインし、役割を確認する導線がある。
- [ ] 全手順に、開始画面・対象・クリック名・成功確認がある。
- [ ] 受付と承認と完了を混同していない。
- [ ] メンバー作成の権限と、作成後編集の制限が両方説明されている。
- [ ] 管理者専用の削除・再開・アカウント発行等をマネージャーに案内していない。
- [ ] 公開範囲、親タスク、複数担当の説明に誤りがない。
- [ ] 送信結果不明に対して連打や自動再送を案内していない。
- [ ] 実画面の画像に氏名・メール・ID・業務情報・パスワード等の実データが含まれていない。
- [ ] 図番号、画像の番号、本文の番号が一致している。
- [ ] 画像の操作箇所が印刷時に読める。必要な拡大図がある。
- [ ] 未撮影画像を代替画像でごまかしていない。
- [ ] 日本語フォントの欠落、文字化け、表のはみ出しがない。
- [ ] 改ページ後に見出しだけが残らず、図と手順が対応している。
- [ ] 制作メモと確認事項は利用者版から分離されている。
- [ ] 完成PDFを各ページ表示して目視確認した（PDFを出す場合）。

## 7. 日次・週次の配布カード

別紙の最短ガイドは、本編の第1章・第2章を基に、各2ページに編集してください。

**メンバーカードの表：**ログイン → 自分の作業 → 詳細 → 完了報告。  
**裏：**納期変更／自分の申請／見つからない・送れないとき。

**マネージャーカードの表：**概要 → 対象確認 → 申請判断。  
**裏：**案件→工程→タスク→担当設定の順序／週次確認／権限外は相談。

初日は「実業務のタスクを1つ見つける」までを必須にし、完了報告や新規登録は実際に必要になったときに使います。練習のためだけに本番データを作成・完了しないよう明示してください。
